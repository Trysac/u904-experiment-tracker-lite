# Security & Threat Model\n\n## Defended\n- **Path Traversal**: Keys, run IDs, and artifact paths are validated against `..` segments and absolute path references.\n- **Atomic Writes**: Data integrity is enforced using `tempfile` staging and `os.replace` to prevent partial/corrupt files.\n- **XSS Attacks**: `build_site` executes `html.escape` (with quote=True) on all experiment names, run names, keys, parameters, metrics, tags, and artifact paths.\n- **Resource Exhaustion**: Strict limits on payload sizes and series lengths prevent disk saturation.\n\n## Not Defended\n- Direct file system manipulation bypasses API validation.\n- Concurrency guarantees outside of atomic file system primitives.\n\n## Limits\n- **Keys**: 1-250 characters.\n- **Values (Params/Tags)**: Max 6,000 characters.\n- **Filter Strings**: Max 1,000 characters.\n- **Metric Series**: Max 100,000 points per key.\n- **Artifacts**: Max 100 MiB per run.
